# Supplemental asset metadata

Per-version JSON describing the assets that Torch must emit but that are **not**
declared in Shipwright's XML: VTX/Vec3s arrays, child DLists, limbs, collision,
`Set_` alternate-header names, MTX offsets, etc. `zapd_to_torch.py
--supplemental-json` injects these into the generated YAMLs.

This is metadata only (names, types, offsets, symbols, counts) — no asset payload.

One file replaces the older `vtx/` + rom-assets + undeclared inputs. Generated by
`generate_supplemental.py` from a **reference O2R + ROM + DMA table**:

```sh
python3 tools/generate_supplemental.py \
    o2r/<version>_<sha>.o2r roms/<version>_<sha>.z64 dma/<version>.json \
    supplemental/<version>.json
```

Committed so the everyday test loop (build Torch → generate YAMLs → compare vs
`manifests/`) needs only a ROM + a Torch build — no reference O2R and no Shipwright
build. Regenerate only when bumping the `shipwright/` submodule.
