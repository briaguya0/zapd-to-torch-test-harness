# Supplemental asset metadata

Per-version JSON describing the assets that Torch must emit but that are **not**
declared in 2ship's ZAPD XML: VTX/Vec3s arrays, child DLists, limbs, collision,
alternate-header names, MTX offsets, etc. `zapd_to_torch.py --supplemental-json`
injects these into the generated YAMLs.

This is metadata only (names, types, offsets, symbols, counts) — no asset payload,
no ROM data.

Generated by `generate_supplemental.py` from a **reference O2R + ROM + DMA table**:

```sh
python3 tools/generate_supplemental.py \
    o2r/<version>_<sha>.o2r roms/mm/<version>_<sha>.z64 dma/<version>.json \
    supplemental/<version>.json
```

Committed so the everyday test loop (build Torch → generate YAMLs → compare vs
`manifests/`) needs only a ROM and a Torch build — no reference O2R.

Empty for now. On OoT the XML declared only ~18.5k of 35386 assets and the rest had
to be recovered this way; whether MM has a comparable gap, and in which categories,
is measured once the YAML generator produces its first output.
