# DMA tables

Per-version JSON mapping each file in the ROM's DMA table to its offsets:

```json
"object_link_child": {
  "virt_start": "0x...", "virt_end": "0x...",
  "phys_start": "0x...", "phys_end": "0x..."
}
```

Offsets and names only — no ROM data.

Generated by `extract_dma.py`, which reads each ROM in `roms/mm/` together with the
matching filelist. The filelists are not produced here: they are vendored upstream in
2ship at `2ship/mm/assets/extractor/filelists/` (`mm.txt` for NTSC-U 1.0, `mm_gc.txt`
for GC US), each a list of files in DMA order.

```sh
python3 tools/extract_dma.py roms/mm dma
```

These also feed the `filelist:` YAML that Torch resolves name-based segment offsets
against — see `assets/yml/README.md`.
